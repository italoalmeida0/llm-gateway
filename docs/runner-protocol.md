# Runner protocol v2 — session-owned logs

Status: **stable**. This is the contract between the daemon (parent) and
the crash-only task runners (docs/runner-plan.md). The protocol is
NEVER load-bearing for output: the session BgTask (RAM + WAL) carries
everything (§4); the socket is a latency optimization.

## Stability rules (eternal)

1. **Receivers ignore message types and fields they do not know.**
   Growth is always additive; nothing ever breaks.
2. **`proto` handshake**: if the two sides disagree on `proto`, they fall
   back to file-only mode silently. A future v2 lives alongside v1.

There is no application-level ACK, ever. TCP gives ordered lossless
delivery while connected (kernel-flushed buffers survive even the
runner's SIGKILL); anything lost is repaired from the session BgTask
(RAM + WAL replay). Socket sends are best-effort and NEVER block the
runner — the session is the buffer.

## Transport

- Loopback TCP, bound to `127.0.0.1`.
- Auth: bearer token, generated by the runner (`crypto/rand`), stored
  ONLY in its state file (mode `0600`) and sent as the first `hello`
  field. This closes the socket against other local processes.
- The runner LISTENS, the parent DIALS: a restarted parent only needs
  files to find every live runner.

## Verbs (exactly five)

| Direction | Type | Payload | Purpose |
|-----------|------|---------|---------|
| both | `hello` | `proto`, `token` (parent→), `logCursor` (parent→), `jobId`, `pid`, `logSize` (runner→) | greeting + auth + cursor exchange |
| runner → parent | `out` | `off` (byte offset in the log), `chunk` (base64) | output chunk; the log is written FIRST |
| both | `ping` | — | liveness |
| parent → runner | `kill` | `reason` | cancel the task (kills the command's process group) |
| runner → parent | `done` | `exitCode`, `endedAt` | terminal outcome (also in the state file) |

`out.chunk` is base64 so offsets stay byte-exact — the dedup key.
Chunks land in the session BgTask (append + WAL), never in a file.

## Files (launch + recovery only)

```
<root>/runners/
  indirect-code-runner-<version>[.exe]      self-copied binary (GC key)
  <jobId>.state.json                        per-task state (below, transient)
  <jobId>.disposition                       background|inline|suppressed (transient)
  <jobId>.launch                            launch claim (transient)
```

Runner files are TRANSIENT: they exist only while the task runs (launch
claim, recovery state, crash-only adoption). At terminal — once every
byte is durable in the session BgTask — the daemon removes state +
disposition + launch immediately. No 7-day retention, no `out/` logs,
no `brain/` copies. The v2 storage migration sweeps v1 leftovers
(`out/*.log`, `brain/bg_*.log`, terminal states).

### Session BgTask (the real contract)

Output lives in the session, not in files. The daemon appends every
chunk to the session's `BgTasks[]` record (RAM tail 100KB + WAL event
per chunk, throttled persistence while idle) and trims to 50KB at
terminal. `TotalLines`/`DroppedLines` counters give `bg_check` stable
line ranges after head discards. BgTasks are never GCed — a bg task is
part of the session transcript forever, like a tool call.

Written IMMEDIATELY at runner start (durability never waits), rewritten
atomically (tmp+rename) on transitions. Readers ignore unknown fields.

```json
{
  "v": 1, "proto": 1, "runnerVersion": "1.0.34",
  "jobId": "…", "sessionId": "…", "kind": "bash", "label": "build",
  "pid": 1234, "startedAt": 1760000000000,
  "logPath": "",   // v1 compat only: v2 keeps output in the session BgTask
  "brainPath": "", // v1 compat only: no brain copies in v2
  "transport": { "type": "tcp", "host": "127.0.0.1", "port": 41234, "token": "…" },
  "status": "running",        // running | done | killed
  "exitCode": null,           // set BEFORE the done transition
  "endedAt": null,
  "heartbeatAt": 1760000000000
}
```

- `pid` plus `processIdentity` identifies the runner incarnation; PID alone
  never authorizes adoption or signalling. `cmdPid`, `cmdPgid`, and
  `commandIdentity` identify the gated command bootstrap.
- `status: done|killed` + `exitCode` IS the completion record and the
  retained-notice source — until the daemon folds it into the session
  BgTask and cleans the files.

### Terminal transition (any outcome: finished / killed / cleaned)

1. Join command-tree cleanup, then write `status` + `exitCode` +
   `endedAt` to the state (atomic, checked publication).
2. The daemon marks the session BgTask terminal (status + trim to
   50KB + WAL fsync) and REMOVES state + disposition + launch
   immediately — no retention window.
3. Send `done` if a parent is connected (fast path only). Publication
   failures retry without re-execution; exhausted retries exit the
   wrapper with 75, which is not the command exit code.
4. Exit immediately. Self-clean: the last runner of a generation removes
   its own version binary when a newer one exists.

### Parent reconciliation (boot + hourly)

- `running` + pid alive + link found (or fresh) → ADOPT (chunks resume
  into the session BgTask).
- `running` + pid alive + old AND unlinkable → orphan: SIGKILL the tree,
  clean the state (F5b — recovery is tried first: the state's
  ids/timestamps correlate to the session transcript/WAL).
- `running` + runner incarnation gone → `outcomeUnknown: true` and explicit
  interrupted outcome. Verify external effects before repeating the command.
- `done`/`killed` → fed to the retained-notice chain (idempotent via the
  transcript's `background_delivery` identity — exactly one wake-up
  turn, ever), then files cleaned.
- GC sweeps leftover terminal states (crash between terminal and
  cleanup) + dead generation binaries. No retention window: the session
  BgTask is the durable record.

## What is deliberately NOT here

Output history (the session BgTask), kill fallback (pid + process
group), liveness fallback (pidalive), completion (state file +
retained notice), delivery acks (offsets + WAL). Any of those keeps
working if this protocol vanishes.

## Crash recovery additions

The multicall binary's internal `--runner-command` role waits on a private pipe.
The runner establishes command ownership and publishes birth identity before
releasing user code. EOF before release exits without executing the payload.
Windows assigns the bootstrap to a runner-owned kill-on-close Job Object before
release; replacing the daemon does not close that independent runner handle.

Execution receipts live under `<root>/executions/<session>/<scope>/`; exclusive
`<jobId>.launch` files prevent relaunch of the same execution. A receipt can link
a foreground runner before a background placeholder reaches the transcript.
Receipts and launch claims are conservatively retained, independently of terminal
state GC. Unverifiable process identities are traced, never blindly killed.

See [crash recovery contracts](daemon-crash-only-hardening.md#implementation-on-dev)
for exact behavior, test coverage, storage failure handling, and POSIX containment
and power-loss limits. These additions do not change the manual V1 migration.
